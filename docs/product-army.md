# Product Army

The repository is evolving from a collection of individual skills into a product-production system.

## Units

- Market Opportunity Discovery — finds painful, monetizable problems.
- Product Architect — converts a validated problem into a minimal product design.
- Existing builders — implement APIs, skills, apps, automations, and agents as appropriate.
- Product Verifier — performs runtime, contract, security, reliability, and regression verification.
- Product Release — packages, documents, deploys, and prepares the product for sale.
- Product Distribution — finds qualified buyers, runs focused outreach, and captures sales signals.
- Product Memory — preserves evidence, decisions, failures, customer feedback, and learning.
- Product Orchestrator — coordinates the pipeline and enforces stage gates.

## Pipeline

`DISCOVER → ARCHITECT → BUILD → VERIFY → RELEASE → DISTRIBUTE → FEEDBACK → MEMORY → IMPROVE`

## Closed loop

The system is not complete when a product ships. Distribution produces customer evidence; Memory preserves it; the Orchestrator uses that evidence to decide whether to improve, reposition, expand, or stop the product.

The goal is not to maximize the number of skills. The goal is to repeatedly turn validated problems into verified, deployable, sellable products and learn from real customer feedback.
