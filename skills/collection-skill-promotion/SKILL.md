# Collection Skill Promotion

1. Preserve the original repository, immutable ref, license, and relevant path.
2. Evaluate two axes independently: reusable Skill material and independent ready-made/near-ready project potential.
3. Never discard a repository because the Skill axis is negative when the project axis is positive.
4. Before creating a Skill, search agent-skills/skills by exact name and semantic purpose. Extend one canonical Skill instead of creating overlapping Skills.
5. Extract the smallest useful reusable procedure into skills/<lowercase-hyphen-name>/SKILL.md. Do not copy an application wholesale.
6. Validate frontmatter, scope, referenced resources, and the real workflow when possible.
7. Promote honestly: READY_TO_USE requires actual usability; missing credentials, network, provider, or runtime means BLOCKED.
8. Preserve provenance for every source contributing to a Skill. Keep independent projects separately tracked.

Canonical flow:

Discover → Preserve → Evaluate both axes → Deduplicate → Extract Skill → Validate → Promote

Do not create a new rule when an existing rule can be strengthened instead.
